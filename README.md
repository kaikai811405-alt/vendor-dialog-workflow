## 📋 專案背景

目標是建立一套自動化工作流：每天將與廠商的對話整理後，自動比對專案與任務，並將執行紀錄寫入 Notion 對應的任務頁面中。

---

## ✅ 完整 SOP

### 核心原則
**一次處理完，最後才確認。** 收到對話後連續執行所有步驟，最後輸出一張執行摘要卡，等使用者一次確認後寫入。

---

### STEP 1｜接收對話輸入

| 平台 | 提供方式 | 注意事項 |
|------|----------|----------|
| Teams | 直接複製對話文字 | 時間戳通常完整，可自動解析 |
| WeChat | 截圖方式提供 | 若截圖無完整日期，需補充一行 `日期：YYYY/MM/DD` |
| Outlook | 複製信件內容 / 直接貼上 .msg 檔案路徑 | 寄件者、時間、主旨皆在 header，解析度最高 |

> ⚠️ 一段對話可能包含多個獨立主題，先列出所有主題，詢問是否一次全部處理，每個主題分別走完整 SOP。

---

### STEP 2｜比對聯絡人

1. 從對話內容自動抓取交談對象（人名、Email、稱呼）
2. 到 **Notion 聯絡人資料庫**（workspace 層級，獨立資料庫）進行比對：
   - 優先比對：Email 關鍵字（最精準）
   - 次要比對：對話中的稱呼
   - 最後比對：姓名/英文名
3. 找到 → 確認身份、公司、模組，**繼續後續步驟不中斷**
4. **找不到 → ⚠️ 立即停下通知使用者，等待提供資料後新增至資料庫，絕不自行猜測**

---

### STEP 3｜判斷所屬專案（第一層比對）

從對話內容抽取專案相關關鍵字（型號、代號、產品名稱等），比對 Workspace 中的專案頁面名稱。

| 比對結果 | 處理方式 |
|----------|----------|
| 唯一比對成功 | 繼續後續步驟，寫入摘要卡確認 |
| 比對到多個候選 | 列入摘要卡的 ⚠️ 欄位，請使用者選擇 |
| 完全比對不到 | ⚠️ **直接停下詢問使用者，禁止猜測** |

> 範例：對話中出現「A704」→ 對應專案頁面「A704」

---

### STEP 4｜判斷所屬任務（第二層比對）

進入對應專案的任務清單資料庫，依下列屬性進行比對：

| 屬性 | 類型 |
|------|------|
| 任務名稱 | Title |
| 部件分類 | Select |
| 類別 | Select |

| 比對結果 | 處理方式 |
|----------|----------|
| 唯一比對成功 | 繼續後續步驟，寫入摘要卡確認 |
| 比對到多個候選 | 列入摘要卡的 ⚠️ 欄位，請使用者選擇 |
| 完全比對不到 | 在摘要卡提議新任務名稱，最後一起確認 |

---

### STEP 5｜整理對話內容

將對話整理為以下結構：

- **對話摘要**：本次溝通的主要內容
- **與廠商溝通重點**：廠商名稱 + 關鍵討論點
- **決策／結論**：本次確認的決定事項
- **Action Items**：後續需要執行的項目（標記我方 / 廠商）
- **SN 資訊**：⭐ **重要！必須單獨識別並留存**
  - 從對話中識別所有 SN 編號（格式通常為大寫字母+數字）
  - 區分「已提供」與「待提供」
  - SN 資訊要填入任務頁面頂部的「SN / 批次」欄位，**不放在執行紀錄中**

---

### STEP 6｜輸出執行摘要卡（一次確認）

完成以上步驟後，輸出一張摘要卡：

```
━━━━━━━━━━━━━━━━━━━━━━━━
📋 執行摘要（共 N 個主題）

【主題 1】
👤 聯絡人：姓名（公司）
📁 專案 > 任務：專案名稱 > 任務名稱
📅 日期：YYYY-MM-DD

📝 對話摘要：...
🤝 溝通重點：...
✅ 決策/結論：...
☑️ Action Items：
  - 項目一（我方）
  - 項目二（廠商）
🔖 SN 資訊：（若有）

⚠️ 待確認事項：（列出不確定的項目）
━━━━━━━━━━━━━━━━━━━━━━━━
確認後寫入 Notion，或告知需要修改的地方。
```

使用者回覆「確認」→ 直接寫入，不再詢問。

---

### STEP 7｜確認後寫入任務頁面

經使用者確認後，依任務範本結構寫入對應 Task page：

**執行紀錄**（寫入 `# 📝 執行紀錄` 區塊）：

```markdown
## YYYY-MM-DD
- **執行內容**：[對話摘要]
- **與廠商溝通**：[廠商名稱 + 溝通重點]
- **決策/結論**：[決策內容]
```

**待辦事項**（寫入 `# 📋 任務描述` 下的 `## ⚠️ 待辦事項`）：

```markdown
- [ ] 待辦項目 (YYYY-MM-DD 新增)
```

後續若對話中提到已完成：

```markdown
- [x] 待辦項目 (YYYY-MM-DD 新增, YYYY-MM-DD 完成)
```

#### 任務狀態自動更新規則

| 情況 | 處理方式 |
|------|----------|
| 任務狀態為「完成」或「中止」，但有新對話寫入 | **自動改回進行中，不詢問** |
| 任務狀態正常 | 不變動 |

---

## ⚠️ 阻斷點（僅這幾種情況才中途停下）

> **核心原則：不確定時，一律通知使用者，絕不自行猜測或寫入。**

| 情況 | 處理方式 |
|------|----------|
| 廠商聯絡人無法比對 | ⚠️ 立即停下通知使用者，提供資料後新增至資料庫 |
| 專案無法判斷（對話無任何線索） | ⚠️ 直接詢問使用者，禁止猜測 |
| 對話含多個主題 | 列出主題清單，詢問是否一次全部處理 |
| WeChat 截圖無日期 | ⚠️ 請使用者補充日期 `日期：YYYY/MM/DD` |
| 任務類型不明確 | 列入摘要卡 ⚠️ 欄位，一起確認 |

**比對到多個候選 → 不停下，列入摘要卡 ⚠️ 欄位讓使用者選擇。**
