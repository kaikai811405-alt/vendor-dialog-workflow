## 📋 專案背景

目標是建立一套自動化工作流：每天將與廠商的對話整理後，自動比對專案與任務，並將執行紀錄寫入 Notion 對應的任務頁面中。

---

## ✅ 完整 SOP

### STEP 1｜接收對話輸入

| 平台 | 提供方式 | 注意事項 |
|------|----------|----------|
| Teams | 直接複製對話文字 | 時間戳通常完整，可自動解析 |
| WeChat | 截圖方式提供 | 若截圖無完整日期，需補充一行 `日期：YYYY/MM/DD` |
| Outlook | 複製信件內容（含 header） | 寄件者、時間、主旨皆在 header，解析度最高 |

> ⚠️ 一段對話可能包含多個獨立主題，需各自拆開處理，每個主題分別走完整 SOP。

---

### STEP 2｜比對聯絡人

1. 從對話內容自動抓取交談對象（人名、Email、稱呼）
2. 到 **Notion 聯絡人資料庫**（workspace 層級，獨立資料庫）進行比對：
   - 優先比對：Email 關鍵字（最精準）
   - 次要比對：對話中的稱呼
   - 最後比對：姓名/英文名
3. 找到 → 確認身份、公司、模組
4. **找不到 → ⚠️ 立即通知使用者，等待提供資料後新增至資料庫，絕不自行猜測**

---

### STEP 3｜判斷所屬專案（第一層比對）

從對話內容抽取專案相關關鍵字（型號、代號、產品名稱等），比對 Workspace 中的專案頁面名稱。

| 比對結果 | 處理方式 |
|----------|----------|
| 唯一比對成功 | 告知使用者準備進入該專案，請確認 |
| 比對到多個候選 | 列出候選清單，請使用者選擇 |
| 完全比對不到 | ⚠️ **直接詢問使用者**，等待明確指定專案名稱 |

> 範例：對話中出現「A704」→ 對應專案頁面「A704」

**⚠️ 重要：無法從對話判斷專案時，必須詢問使用者，不可自行猜測或進入第二層**

---

### STEP 4｜判斷所屬任務（第二層比對）

進入對應專案的任務清單資料庫，依下列屬性進行比對：

| 屬性 | 類型 |
|------|------|
| 任務名稱 | Title |
| 部件分類 | Select |
| 類別 | Select |

| 比對結果 | 處理方式 |
|----------|----------|
| 唯一比對成功 | 告知使用者「準備寫入 \[專案\] > \[任務名稱\]」，請確認後才執行 |
| 比對到多個候選 | 列出候選清單，請使用者選擇 |
| 完全比對不到 | ⚠️ **詢問使用者建立新任務所需最基本資訊，直接建立至任務清單** |

#### STEP 4.1｜任務比對失敗時的新增流程

當無法比對到任務時，詢問使用者以下最基本資訊：

1. **任務名稱**（可由 Claude 建議，使用者確認）
2. **部件分類**（依資料庫選項）
3. **類型**：Task / Bug / RMA（不確定時直接問）
4. **狀態**
5. **截止日期**（如有）

確認後依對應範本建立任務頁面，並將對話紀錄與 Action Items 填入正確區塊。

---

### STEP 5｜整理對話內容

將對話整理為以下結構：

- **對話摘要**：本次溝通的主要內容
- **與廠商溝通重點**：廠商名稱 + 關鍵討論點
- **決策／結論**：本次確認的決定事項
- **Action Items**：後續需要執行的項目
- **SN 資訊**：⭐ **重要！必須單獨識別並留存**
  - 從對話中識別所有 SN 編號（格式通常為大寫字母+數字）
  - 區分「已提供」與「待提供」
  - SN 資訊要填入任務頁面頂部的「SN / 批次」欄位，**不放在執行紀錄中**

---

### STEP 6｜確認後寫入任務頁面

經使用者確認後，依任務範本結構寫入對應 Task page：

```markdown
# 📋 任務描述
*(任務目標說明)*

## ⚠️ 待辦事項
- [ ] 待辦項目 (YYYY-MM-DD 新增)
```

執行紀錄寫入 `# 📝 執行紀錄` 區塊：

```markdown
## YYYY-MM-DD
- **執行內容**：[對話摘要]
- **與廠商溝通**：[廠商名稱 + 溝通重點]
- **決策/結論**：[決策內容]
```

#### ⚠️ 待辦事項處理

如果對話中有 Action Items（待辦事項）：

1. **識別待辦事項**：從對話中提取需要執行的項目
2. **寫入位置**：在任務頁面的「📋 任務描述」區塊下方，建立「## ⚠️ 待辦事項」區塊，條列為 checkbox 格式
3. **格式範例**：

```markdown
# 📋 任務描述
*(任務目標說明)*

## ⚠️ 待辦事項
- [ ] 提供物料改善後的 SN 給 DOE (2026-04-29 新增)
- [ ] 確認耳膜檢驗設備的破皮檢測能力 (2026-04-29 新增)
```

4. **後續更新機制**：如果後續對話中提到任務已完成，將對應的 `- [ ]` 改為 `- [x]`，在後方註明完成日期

```markdown
## ⚠️ 待辦事項
- [x] 提供物料改善後的 SN 給 DOE (2026-04-29 新增, 2026-05-02 完成)
- [ ] 確認耳膜檢驗設備的破皮檢測能力 (2026-04-29 新增)
```

## ⚠️ 異常處理原則

> **核心原則：不確定時，一律通知使用者，絕不自行猜測或寫入。**

| 異常情況 | 處理方式 |
|----------|----------|
| 廠商聯絡人無法比對 | ⚠️ 立即通知使用者，提供資料後新增至資料庫 |
| 專案無法判斷 | ⚠️ 直接詢問使用者，禁止猜測 |
| 任務無法比對 | ⚠️ 詢問最基本資訊，直接建立新任務 |
| 對話含多個主題 | 拆分為多筆，各自跑完整 SOP |
| WeChat 截圖無日期 | ⚠️ 請使用者補充日期 `日期：YYYY/MM/DD` |
| 比對到多個候選 | 列出選項讓使用者選擇，不自行決定 |
| 任務類型不明 | ⚠️ 詢問使用者：Task / Bug / RMA |
